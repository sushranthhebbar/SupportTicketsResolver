Declaration of AI tool use

I used Claude Code, Anthropic's command-line coding assistant running Claude models, throughout this project, and the use was substantial. Working from my instructions, it wrote and edited code in the repository, including the pipeline, guardrails, evaluation harness, review application and tests. It wrote the analysis scripts for calibration, error analysis, confidence intervals and the fairness audit, ran the experiments and evaluation runs, and read the 50 validation drafts against the cited articles. It drafted the analysis documents in the repository (the development error analysis, the governance documents, the credential scan) and this report, and it drafted text in the stage workbooks and the effort log, including the estimated hours. Besides the assistant I relied on the supplied course pack (transcripts, data sets, specifications and templates), on open-source libraries (Chroma, a LangChain text splitter, the MiniLM sentence embedding model, FastAPI, requests, python-dotenv and python-docx), and on Qwen 3.8 27B, served by Groq, as the language model inside the system. The prompts that run in the system were drafted with the assistant and are listed in Table A1 (Appendix A).

The course asks that the problem statement, the interpretation of results and the reflection come from my own judgement. The problem statement in Section 3 is the text from my discovery workbook. The interpretation and reflection in Sections 7, 9 and 10 were drafted by the assistant from my workbooks and the result files. Every number in this report comes from a file in the repository.

There were places where I overrode or corrected the assistant. It told me a validation run did not exist when I had in fact started one, and I corrected that. The course documents gave the wrong deadline and I corrected it to 22 November. I decided not to carry out the two-assessor review of the drafts for lack of time, although the assistant had built the review packet, so the hallucination rate and citation accuracy are reported as not measured. I chose which of its suggested guardrail changes to build (the input check and the logging of classifier failures) and which to leave as known gaps. Its first guardrail demonstration used an invented key that resembled a real one, and the repository host's secret scanner rejected the push, so I approved rewriting my unpushed commits to remove it; a scan of the whole history found no real credential. The hours in the effort log are estimates that the assistant produced from the commit history and plan, and not a timesheet.
