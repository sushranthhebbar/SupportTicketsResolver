4.1 What is deliberately out of scope

The PRD lists what it does not build and why. There is no autonomous chatbot, because the head of support's worst case is a confident wrong answer and the customer wants a person to confirm. Agents are not replaced. The knowledge base is not rewritten, since most answerable tickets already have an article that retrieval finds. Agents' personal answer files are not used as sources, because Daniel warns they may be wrong. Tiers, service agreements and staffing are CloudServe's decisions.

4.2 Assumptions written down in advance

Version 1.0 recorded three assumptions: the documentation is usable as an answer source, tickets contain enough context for a useful draft, and agents will review drafts properly. Version 1.0 also rested on three that I had not written down, namely that a confidence score can decide which tickets get an automatic answer, that urgency can be predicted from the text and used to route, and that a free model provider can run the evaluation unattended. Section 9 reports how each of the six turned out.

4.3 Success measures

The measures in the PRD fall into two groups. The offline evaluation can report intent precision and recall, retrieval hit rate, a citation proxy, latency and group gaps. First contact resolution, time to first reply and satisfaction need a supervised pilot with real outcomes, so the evaluation reports them as unavailable and never fills them from the historical baseline. That is why this report cannot say whether the assistant improves CloudServe's first contact resolution.
