Appendix D. Workbooks, logs and how to reproduce

Submitted with this report. The five stage workbooks (discovery, requirements version 2.0, prompt library, sprint plan, and the requirements revision log) and the effort log, in the workbooks folder; the complete repository in the source code folder. Supporting documents in the repository: docs/governance.md, docs/governance_coverage_check.md, docs/validation_draft_review.md, docs/validation_latency_and_fairness.md, docs/development_error_analysis.md, docs/accuracy_uncertainty_and_fairness.md, docs/urgency_and_label_noise.md, docs/credential_scan.md.

Effort. The effort log totals about 80 hours across three weeks to 11 November, with the report, video and packaging still to complete. Task entries between 26 October and 11 November were reconstructed on 11 November from the commit history and project notes, and the hours are estimates, not a timesheet. Build and revision took far longer than planned (about 64 hours against 25 planned for the original backlog items), because calibration, error analysis, the routing policy, the review workflow and repeated runs under the free-tier quota were not in the plan.

Dates of evaluation runs. First validation run 1 November 2026 (6 of 80 tickets before rate limiting); paced run 2 November (80 of 80, prompt PR-03 v2, intent 88.8%); final run in the final configuration completed by 10 November (80 of 80, no errors, intent 91.3%), report regenerated 11 November. The hidden 120-ticket evaluation set: not run by me, zero times.

Reproduction. Install the requirements, copy .env.example to .env and add a model key, run python -m pytest tests -v for the tests, python scripts/run_evaluation.py --input <tickets.json> --output <results.jsonl> --processor src.pipeline:process_ticket for an evaluation run (add --resume to continue an interrupted run), and uvicorn src.app:app for the review page. The demonstrations are scripts/demo_guardrail_ticket.py and scripts/demo_failure_modes.py.
